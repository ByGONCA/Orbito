# Orbito — Permanent Repository Organisation Policy & Governance

**Authority:** Senior Software Architect & Lead Development Orchestrator  
**Status:** Canonical & Mandatory  
**Applicability:** All Human Developers, AI Agents, Subagents, and Git Worktrees  

---

## 1. Core Principles

The repository root is reserved strictly for essential configuration files, canonical entry points, and top-level infrastructure directories. Cluttering the repository root with transient audit reports, feature-specific markdown files, generated outputs, or local runtime data is strictly forbidden.

All documentation, audits, guides, and architectural specifications must be maintained within the centralized `docs/` hierarchy.

---

## 2. Directory & Root Layout Responsibilities

| Path | Category | Purpose | Governance Rule |
| :--- | :--- | :--- | :--- |
| **`.agents/`** | Operational Infrastructure | Multi-agent coordination hub, agent definitions, workflows, and task lifecycles. | Managed via Single Writer Protocol. Read-only for feature specialists. |
| **`.ai-workspace-data/`** | Persistent Runtime Data | Local SQLite databases (`app.sqlite`, `index.sqlite`), WAL journals, and installed extensions. | **GITIGNORED.** Never commit runtime databases or private state to source control. |
| **`.github/`** | CI/CD Infrastructure | GitHub Actions workflows (`test.yml`) and repository assets. | Changes require Lead Architect review. |
| **`bin/`** | CLI Executable | Orbito developer and automation CLI (`bin/orbito.js`). | Source-controlled; packaged with the application. |
| **`docs/`** | Central Documentation | All documentation, audits, development guides, and specifications. | Organized into strict subdirectories (see Section 3). |
| **`graphify-out/`** | Codebase Knowledge Graph | AST and dependency graph generated by Graphify. | Keep graph AST in sync; cache directories remain gitignored. |
| **`node_modules/`** | Dependencies | Third-party packages installed via `npm`. | **GITIGNORED.** Managed exclusively via `package.json` and `package-lock.json`. |
| **`out/`** | Build Output | Bundled Electron main, preload, and renderer assets. | **GITIGNORED.** Generated via `npm run build`. |
| **`plugins/`** | Extension Development | Canonical example plugins and workspace extension templates. | Source-controlled plugin development source. |
| **`resources/`** | App Assets | Application icons, window badges, and packaging media. | Source-controlled; consumed during Electron packaging. |
| **`scripts/`** | Tooling & Automation | Build scripts, coordination validators, and repository structure validators. | Source-controlled; invoked via `npm run`. |
| **`src/`** | Application Source | Main (`src/main`), Preload (`src/preload`), Renderer (`src/renderer`), and Shared (`src/shared`). | Source-controlled domain code governed by `OWNERSHIP.json`. |
| **`tests/`** | Test Suites | Vitest integration and unit tests. | Source-controlled; must pass 100% in CI. |

## 3. Documentation Hierarchy (`docs/`)

All documentation must reside in one of the following directories:

```text
docs/
├── README.md               # Central navigation index for all Orbito documentation
├── architecture/           # System, engine, security, database, and prompt architecture
├── audits/                 # Security audits, performance benchmarks, and phase verification reports
├── development/            # Setup, testing, AI context, and repository governance policies
├── agents/                 # Multi-agent architecture, orchestration, and task protocols
├── editor/                 # Code editor architecture, performance, and Monaco/LSP roadmap
├── plugins/                # Plugin SDK, manifest specifications, and CLI reference
├── releases/               # Release notes, changelog, and versioning guides
└── reference/              # PRD, engineering roadmap, and node specifications
```

---

## 4. Root-Level File Whitelist

Only the following files are permitted in the repository root:

1. **Canonical Entrypoints:**
   - `README.md` — Concise project introduction, quickstart, and link to `docs/README.md`.
   - `AGENTS.md` — Authoritative instructions for AI coding agents.
   - `CLAUDE.md` — Claude tool instructions referencing `AGENTS.md`.
2. **Package & Build Configuration:**
   - `package.json`
   - `package-lock.json`
   - `electron.vite.config.ts`
   - `postcss.config.js`
   - `tailwind.config.js`
   - `tsconfig.json`
   - `tsconfig.node.json`
   - `tsconfig.web.json`
   - `vitest.config.ts`
   - `skills-lock.json`
3. **Git Configuration:**
   - `.gitignore`
   - `.gitattributes`

**Rule:** Creating any other `.md` or text file directly at the root will cause `npm run validate:structure` to fail and block CI.

## 5. Mandatory Workflow for Adding Documentation

When any developer or AI agent authors documentation or an audit report:

1. **Classify:** Determine the appropriate category:
   - System or engine design → `docs/architecture/`
   - Audit, benchmark, or remediation report → `docs/audits/`
   - Developer guide, setup, or workflow → `docs/development/`
   - Agent orchestration or coordination → `docs/agents/`
   - Editor or syntax engine → `docs/editor/`
   - Plugin, extension, or SDK → `docs/plugins/`
   - Release note or changelog → `docs/releases/`
   - PRD or broad reference → `docs/reference/`
2. **Write:** Place the file in the designated subdirectory. Use relative links for all internal references.
3. **Index:** Add the document to `docs/README.md` under its respective category.
4. **Validate:** Run `npm run validate:structure` before submitting or completing the task.

## 6. Structure Validator & Exception Governance

The repository includes an automated structure validator:
```bash
npm run validate:structure
```

### Validator Checks
- Verifies that no unauthorized Markdown files exist in the root.
- Ensures all required `docs/` subdirectories exist.
- Ensures `docs/README.md` exists and valid links resolve.
- Verifies that runtime data directories (`.ai-workspace-data`) and build directories (`out`) are not tracked by Git.

### Adding Legitimate Root Configuration Exceptions
If a newly introduced tool or build system strictly requires a configuration file in the repository root, add the filename to the `PERMITTED_ROOT_FILES` array in [`scripts/validate-structure.js`](file:///C:/Users/gonca/OneDrive/Documents/Projects/Orbito/Orbito/scripts/validate-structure.js) and document the rationale in an ADR.
